# Български типографски правила за дигитален текст

Практически типографски насоки за съвременен български текст:
- UI
- локализация
- субтитри
- документация
- уеб съдържание
- чат системи
- техническо писане
- редакторски текст

Целта е:
- четимост
- последователност
- естествено българско форматиране

а не:
- типографски перфекционизъм.

Българската дигитална типография трябва да остане практична и използваема.

Тук има два основни слоя:
- `A–G`: предимно нормативна и редакторска опора за стандартен български текст
- `H`: UX, локализационна и техническа евристика

Когато има напрежение между строга типографска традиция и екранна използваемост, файлът по подразбиране предпочита четимото и устойчиво дигитално решение.

# A. Кавички

## A.1. Български кавички

**Статут:** силна нормативна и редакторска опора.

Използвайте:
- `„ “` за основни кавички
- `‚ ‘` за вложени кавички

### Примери

| Грешно | Правилно |
|---|---|
| "текст" | „текст“ |
| „"вложен текст"“ | „‚вложен текст‘“ |

---

## A.2. Прави кавички

**Статут:** практическо техническо правило.

Правите кавички:
- `" "`
- `' '`

са допустими само в:
- код
- терминални команди
- JSON/YAML
- имена на файлове
- URL адреси
- програмни контексти

### Примери

| Контекст | Допустимо |
|---|---|
| Python | `"text"` |
| JSON | `"name": "value"` |
| Терминал | `git commit -m "fix"` |

---

## A.3. UI етикети

**Статут:** редакторска и UX практика.

UI етикетите може да използват кавички, когато се отнасят до:
- бутони
- елементи от меню
- действия

### Пример

```text id="h1s6ng"
Натиснете „Запази“.
````

---

## A.4. Интервали около кавичките

**Статут:** силна нормативна и редакторска опора.

Не добавяйте интервали:

* вътре в кавичките.

### Грешно vs правилно

| Грешно     | Правилно |
| --------- | ------- |
| „ текст “ | „текст“ |

---

# B. Тирета и черти

## B.1. Късо тире (`-`)

**Статут:** редакторска и дигитална практика.

В практическото българско дигитално писане:

* късото тире е най-често срещаният разделител.

Използва се за:

* сложни думи
* CLI флагове
* markdown
* имена на файлове
* неформално отделяне
* технически контекст

### Примери

| Правилно      |
| ------------ |
| северо-запад |
| anti-pattern |
| run_uv.bat   |
| --help       |

---

## B.2. Средно тире (`–`)

**Статут:** силна редакторска практика.

Използвайте главно за:

* диапазони
* периоди
* интервали

### Примери

| Грешно     | Правилно   |
| --------- | --------- |
| 2020-2025 | 2020–2025 |
| 10-15 дни | 10–15 дни |
| стр. 5-9  | стр. 5–9  |

---

## B.3. Дълго тире (`—`)

**Статут:** редакторска практика, не универсално изискване.

Дългото тире може да се използва в:

* художествен текст
* редакторски текст
* формална типография

Но:

* то НЕ е задължително във всеки български дигитален текст.

### Важна бележка

Българската дигитална типография е по-прагматична от строгата печатна типография.

Четимостта и използваемостта са с приоритет при:

* UI
* субтитри
* markdown
* игри
* техническа документация
* чат системи

---

## B.4. Избягвайте прекомерната употреба на тирета

**Статут:** редакторска практика.

Твърде многото тирета:

* накъсват ритъма
* имитират преводна пунктуация
* намаляват четимостта

### Слабо vs по-добре

| Слабо                                 | По-добре                             |
| ------------------------------------ | ---------------------------------- |
| Това - както вече казахме - е важно. | Това, както вече казахме, е важно. |
| Проектът - новата версия - е готов.  | Проектът (новата версия) е готов.  |

---

## B.5. Знак минус

**Статут:** техническа и редакторска препоръка.

Използвайте:

* `−`
  за математически минус, когато е възможно.

### Примери

| Грешно  | Правилно |
| ------ | ------- |
| -5     | −5      |
| 10 - 3 | 10 − 3  |

В нормален текст и в техническа среда:

* стандартното късо тире е приемливо.

# C. Интервали

## C.1. Без интервал преди пунктуация

**Статут:** силна нормативна и редакторска опора.

### Грешно vs правилно

| Грешно         | Правилно      |
| ------------- | ------------ |
| текст , текст | текст, текст |
| текст !       | текст!       |

---

## C.2. Интервал след пунктуация

**Статут:** силна нормативна и редакторска опора.

### Грешно vs правилно

| Грешно         | Правилно        |
| ------------- | -------------- |
| текст,текст   | текст, текст   |
| текст.Следващ | текст. Следващ |

---

## C.3. Без интервали вътре в скоби

**Статут:** силна редакторска практика.

### Грешно vs правилно

| Грешно        | Правилно    |
| ------------ | ---------- |
| ( текст )    | (текст)    |
| [ стойност ] | [стойност] |

---

## C.4. Числа и интервали

**Статут:** силна редакторска практика.

В редактиран текст големите числови групи обикновено се отделят с интервали.

### Грешно vs правилно

| Грешно   | Правилно   |
| ------- | --------- |
| 1000000 | 1 000 000 |
| 250000  | 250 000   |

---

## C.5. Числа и мерни единици

**Статут:** силна редакторска практика.

В редактиран текст обикновено оставяйте интервал между:

* число
* мерна единица

### Примери

| Грешно | Правилно |
| ----- | ------- |
| 5кг   | 5 кг    |
| 20°C  | 20 °C   |
| 50%   | 50 %    |

Бележка:
- в някои продукти и интерфейси `%` може да стои без интервал поради технически или визуални ограничения;
- в последователен редактиран текст е по-добре да се избере един модел и да се спазва навсякъде.

---

## C.6. Непрекъсваеми интервали

**Статут:** редакторска и техническа препоръка.

Непрекъсваемите интервали се препоръчват в:

* издателски текст
* UI
* внимателно форматиран текст

Но:

* обикновените интервали са приемливи в обикновен текст и чат системи.

# D. Многоточие

## D.1. Знак за многоточие

**Статут:** силна редакторска практика.

Предпочитайте:

* `…`
  вместо:
* `...`

### Грешно vs правилно

| Грешно    | Правилно |
| -------- | ------- |
| чакай... | чакай…  |

---

## D.2. Избягвайте прекомерното многоточие

**Статут:** редакторска практика.

Твърде многото многоточия:

* отслабват яснотата
* създават изкуствена драматичност
* намаляват четимостта

### Слабо vs по-добре

| Слабо                  | По-добре           |
| --------------------- | ---------------- |
| Може би... не знам... | Може би не знам. |
| Това е странно...     | Това е странно.  |

---

## D.3. Многоточие в реплики

**Статут:** редакторска практика.

Многоточието е приемливо, когато:

* колебанието е важно
* прекъсването е важно
* ритъмът е важен

Не го използвайте автоматично във всеки емоционален текст.

---

## D.4. Избягвайте смесена драматична пунктуация

**Статут:** редакторска практика.

### Грешно vs по-добре

| Грешно | По-добре |
| ----- | ------ |
| ...?! | ?      |
| !!!   | !      |
| ????? | ?      |

---

# E. Числа и дати

## E.1. Десетичен разделител

**Статут:** силна нормативна и редакторска опора.

Българският стандарт използва:

* десетична запетая

### Грешно vs правилно

| Грешно | Правилно |
| ----- | ------- |
| 3.14  | 3,14    |
| 0.5   | 0,5     |

---

## E.2. Дати

**Статут:** нормативна и редакторска опора с контекстна употреба.

### Предпочитани формати

| Контекст      | Формат          |
| ------------ | --------------- |
| Обикновен текст | 15 март 2026 г. |
| Таблици/форми | 15.03.2026      |

Избягвайте:

* смесени формати
* дати със слешове, освен ако не са технически необходими

---

## E.3. Час

**Статут:** силна редакторска практика.

### Предпочитан формат

```text id="8d4a4q"
14:30
```

### Грешно vs правилно

| Грешно | Правилно |
| ----- | ------- |
| 14.30 | 14:30   |
| 9:5   | 9:05    |

---

## E.4. Валута

**Статут:** контекстна редакторска практика.

Използването на валута зависи от контекста на продукта, документа или примера.

Важното тук е:
- символът или съкращението да са правилно изписани;
- форматът да е последователен;
- интервалите да не се смесват без причина.

### Примери

| Контекст                      | Пример |
| ---------------------------- | ------- |
| Цена в евро | 25 € |
| Цена в левове | 25 лв. |

### Интервали

| Грешно | Правилно |
| ----- | ------- |
| 25€   | 25 €    |
| 25лв. | 25 лв.  |

---

## E.5. Редни числителни

**Статут:** практическа редакторска препоръка; при колебание проверявайте отделно.

В дигитален и редактиран текст редните числителни често се изписват с кратка, четима форма.

### Примери

| Правилно |
| ------- |
| 1-ви    |
| 2-ри    |
| 3-ти    |
| 15-и    |

Избягвайте несистемни или копирани от други езици модели.

# G. Специални символи

## G.1. Знак номер

**Статут:** силна редакторска практика.

В обикновен български текст предпочитайте:

* `№`

### Грешно vs правилно

| Грешно | Правилно |
| ----- | ------- |
| #5    | № 5     |

---

## G.2. Знак за умножение

**Статут:** техническа и редакторска препоръка.

Предпочитайте:

* `×`
  вместо:
* `x`

### Грешно vs правилно

| Грешно     | Правилно     |
| --------- | ----------- |
| 1920x1080 | 1920 × 1080 |
| 3 x 4     | 3 × 4       |

---

## G.3. Знак за градус

**Статут:** силна редакторска практика.

### Правилни примери

| Правилно |
| ------- |
| 20 °C   |
| 90°     |

---

## G.4. Авторско право и търговски марки

**Статут:** справочна редакторска практика.

### Примери

| Символ | Значение              |
| ------ | -------------------- |
| ©      | авторско право            |
| ™      | търговска марка            |
| ®      | регистрирана търговска марка |

---

## G.5. Българското ѝ

**Статут:** силна нормативна и редакторска опора.

Използвайте:

* `ѝ`
  за:
* „на нея“

### Грешно vs правилно

| Грешно          | Правилно        |
| -------------- | -------------- |
| й даде книгата | ѝ даде книгата |

Не заменяйте механично:

* `ѝ`
  с:
* `й`

# H. Типография за UI и локализация

## H.1. Четимостта е по-важна от перфекционизма

**Статут:** UX и локализационна евристика.

При локализация:

* четимостта е по-важна от типографската чистота.

Особено при:

* субтитри
* UI
* игри
* мобилни интерфейси
* чат системи

---

## H.2. Кратък UI текст

**Статут:** UX и локализационна евристика.

Предпочитайте:

* по-кратки формулировки
* по-проста пунктуация
* по-малко декоративни знаци

### Слабо vs по-добре

| Слабо       | По-добре    |
| ---------- | --------- |
| Потвърди!  | Потвърди  |
| Настройки: | Настройки |

---

## H.3. Четимост на субтитрите

**Статут:** UX и локализационна евристика.

Субтитрите трябва:

* да избягват пунктуационен шум
* да избягват прекомерно накъсване
* да пазят говоримия ритъм
* да остават лесни за бързо четене

---

## H.4. Технически среди

**Статут:** техническо правило.

Техническите среди може умишлено да използват:

* ASCII пунктуация
* прави кавички
* прости тирета

Не „поправяйте“ автоматично текст, чувствителен към синтаксиса.

---

## H.5. Съобразяване с Markdown

**Статут:** техническо правило.

Синтаксисът на Markdown трябва да остане непипан.

### Примери

| Синтаксис        |
| ------------- |
| `# Heading`   |
| `- List item` |
| `**bold**`    |
| `` `code` ``  |
